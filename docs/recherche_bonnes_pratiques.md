# Recherche web (11 oct 2026) — bonnes pratiques de wikis de jeu orientés joueurs
Sources consultées :
1. Soulbound Wiki — Layout guide / Manual of Style (https://wiki.soulbound.game/Wiki:Layout_guide , /Wiki:Manual_of_Style) : phrase d'intro d'une ligne d'abord ; ordre de sections fixe par type de page (modèle OSRS Wiki) ; métadonnées dans un infobox, profondeur optionnelle dans des sections repliables, liens connexes dans un navbox en pied ; sous-sujets volumineux déportés vers des sous-pages.
2. GameDev.net — « Building Better Game Guides » (https://gamedev.net/blogs/entry/2298362-building-better-game-guides-what-ive-learned-about) : partir de la question du joueur, petites sections scannables, exemples, expliquer pourquoi une mécanique compte, information progressive pour niveaux différents, terminologie cohérente, contenu mis à jour par sections.
3. Fandom/Gamepedia — SEO best practices (https://help.fandom.com/wiki/SEO_best_practices) : pages de catégories larges avec tableaux/listes digestes, pages hub liées en évidence depuis l'accueil, lier les termes à la première mention, répondre à des questions précises de joueurs.
4. HCI in Games (ACM) — étude d'utilisabilité des wikis communautaires (https://dl.acm.org/doi/10.1007/978-3-032-30408-7_17) : les novices ont besoin d'« échafaudage visuel », les experts apprécient la densité ; piège « forme avant fonction » (trop d'esthétique nuit à la retrouvabilité) ; interface à deux niveaux (résumé + détails).
5. DEV.to — Live Game Wiki with Astro (https://dev.to/hongyuncheng/building-a-live-game-wiki-with-astro-architecture-seo-and-data-reliability-4mkh) : static-first, données volatiles structurées et datées, fiabilité visible, composants réutilisables (tableaux, avertissements, notes de source), URLs par intention.
6. Medium — « How to design a game wiki that actually ranks » : accueil = hub (qu'est-ce que le jeu, quoi faire en premier, sous-thèmes), navigation à 2–3 niveaux, fil d'Ariane vers le hub, 3–8 liens internes pertinents, sections H2 en forme de questions, « lecture suivante ».
7. DEV.to — Version-aware game wiki (https://dev.to/captainchaozi/designing-a-version-aware-game-wiki-for-early-access-12lc) : afficher la version/date courante, marquer le contenu périmé, entrées orientées tâches.
8. Fandom Help:Infoboxes (https://community.fandom.com/wiki/Help:Infoboxes) : un infobox par type de contenu, fiche récapitulative de stats clés, champs vides masqués.
